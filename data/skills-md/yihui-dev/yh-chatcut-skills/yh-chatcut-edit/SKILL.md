# yh.edit for ChatCut

## 核心原则

- 仅在已安装并可调用 ChatCut、且存在可编辑项目时执行；缺少 ChatCut 能力、项目或主素材时，说明缺失项并停止。
- 使用 ChatCut 创建可继续编辑的项目，不用外部脚本烘焙成不可编辑成片。
- 先完成 A-Roll，再强制暂停；只有用户明确确认后才能继续 B-Roll。
- 以当前项目、时间线、素材库和用户给出的素材名称为事实来源，不猜测素材内容或对应位置。
- 每次修改后验证项目状态和关键画面。任何工具错误、素材缺失、时间线冲突或结果不确定都要立即停下并报告，不要自动进入下一阶段。
- 保留用户已有编辑和无关轨道，不清空时间线，不覆盖用户未授权的修改。

## 工作流状态机

严格按以下状态推进：

`准备 -> A-Roll -> 等待确认 -> B-Roll -> 字幕 -> 音效 -> 背景音乐 -> 总检`

不得跳过“等待确认”，也不得把全部阶段放进一次连续执行。

## 0. 准备

1. 读取 ChatCut 项目、主时间线、素材库和已有轨道。
2. 确认主口播素材、逐字稿、画幅、帧率、用户指定的 B-Roll 素材与配对关系。
3. 优先加载并遵循 `chatcut:chatcut-plugin-basics`；按阶段加载 `chatcut:talking-head-guide`、`chatcut:asset-import`、`chatcut:transcription`、`chatcut:voice`、`chatcut:music` 和 `chatcut:verification`。
4. 若素材或映射不完整，先做不依赖缺失信息的准备工作，再提出最小必要问题。

## 1. A-Roll 剪辑

1. 只处理主口播及其人物画面：删除明显停顿、重复、口误、卡壳和无内容的前后空白。
2. 保持原意和叙事顺序，不为追求短而删掉论据、转折或必要呼吸。
3. 检查每个切点，避免吞字、断词、突兀跳音和不自然的半句话。
4. 默认把所有有效口播片段调整为 `1.1x`；若用户明确要求其他速度，以用户要求为准。保持音高自然，并让所有后续工作基于这条最终节奏的时间线。
5. 当主口播为人物画面时，在钩子、观点落点、数字金额、反转或情绪重音等关键语义处适度放大人物画面（Punch-in），强化重点和视觉节奏；若用户明确要求保持画面不变或锁定 A-Roll，则不执行。
6. 普通景别保持当前基础比例（未调整时通常为 `100%`），重点景别原则上在基础比例上放大 `5%–15%`；素材清晰度不足时降低放大幅度，不得因追求近景造成明显模糊。
7. 放大应从重点句开头或重音处切入，随语义结束恢复普通景别；优先使用干净的景别切换，避免在半句话中随意变化、连续推拉或每句话机械缩放。相邻两次放大之间保留正常景别，使重点形成对比。
8. 放大后检查人物眼睛、头顶、手势和字幕安全区，避免错误裁切；允许用景别变化弱化画面跳切，但不得用它掩盖吞字、断词或不自然的音频切点。
9. 不添加 B-Roll、字幕、音效、背景音乐或 MG 动画。
10. 从头到尾试听并抽查切点和景别变化，确认口播连贯、没有重复、没有明显空拍，人物放大与语言重音准确对应。

### A-Roll 确认节点（必须暂停）

A-Roll 完成后必须：

1. 简要报告完成内容、成片时长、删除或保留的争议点、已应用的口播速度，以及 Punch-in 使用位置和比例范围。
2. 让用户先预览，并明确询问是否确认 A-Roll、是否可以进入 B-Roll。
3. 立即结束当前执行。不要在同一轮继续添加 B-Roll、字幕、音效或音乐。

只有收到类似“确认”“A-Roll 可以”“继续做 B-Roll”的明确回复，才进入下一阶段。含糊回复、补充意见或报错都不算确认；先修正 A-Roll，再重新等待确认。

## 2. B-Roll

1. 先读取用户指定素材，按逐字稿语义和用户给出的对应关系放置。
2. 用户明确指定某句话使用某个文件时，严格使用该文件，不自行替换。
3. 保留 A-Roll 原声，以 B-Roll 覆盖画面；不要让 B-Roll 自带音频干扰口播，除非用户明确要求。
4. B-Roll 的入点跟随关键词，出点跟随语义结束；避免无意义的频繁切换和长时间静止配图。
5. 图片比例不匹配时，优先保证核心信息完整可见；允许裁掉无关底部或留出设计性边距，但不要裁掉标题、产品主体或关键文字。
6. 只有在素材不足且用户允许时才补充通用配图、拼贴或简约 MG；默认不生成与产品无关的装饰素材。
7. 完成后逐段核对素材名称、口播语义、时间范围和画面安全区。

## 3. 字幕

1. 基于最终 1.1 倍速时间线生成字幕，使用简体中文。
2. 按语义短句分卡，不按固定字数机械截断；“AI 剪辑 Agent”、产品名、金额和完整词组不得拆到两张卡。
3. 默认移除中文逗号和英文逗号，保留确有必要的问号、感叹号、句号与数字符号。
4. 单卡优先一到两行，保证大字号下完整显示；确需换行时在自然语义边界换行。
5. 检查专有名词、数字、英文大小写以及每张卡的入点和出点。

## 4. 强调音效（可选）

1. 只在钩子、观点落点、数字金额、反转、素材切入或重要转场处添加音效。
2. 优先使用轻量的 whoosh、pop、click、hit、cash 或 riser 类音效；选择应服务语义，不要每句话都加。
3. 控制音量和时长，不能盖住人声；避免连续堆叠相似音效。
4. 对所有音效逐个试听，检查是否与画面和重音同步。

## 5. 背景音乐

1. 选择节奏轻快、现代、不过度抢戏的背景音乐，和口播主题及画面气质一致。
2. 从开头铺到结尾，必要时循环或裁切；避开突兀断点。
3. 把音乐稳定压在人声下方，在钩子、转折和结尾做轻微动态变化；不得影响口播清晰度。
4. 若需要生成音乐，使用 `chatcut:music`；若已有合适曲目，优先复用项目素材库。

## 6. 总检

1. 从头到尾播放完整时间线，检查口播连贯性、B-Roll 映射、字幕语义、音效同步和音乐音量。
2. 在开头、A-Roll 切点、Punch-in 入出点、B-Roll 入出点、字幕长句、音效重音和结尾各做一次画面验证。
3. 确认没有黑帧、重叠字幕、素材离线、音频爆音、画面比例错误或时间线尾部残留。
4. 汇报实际完成内容和仍需用户判断的项目，不把未验证结果描述为完成。

## 执行边界

- 用户只要求某一个阶段时，只执行该阶段，不自动补齐整套流程。
- 用户在确认门之前提出修改时，保持在 A-Roll 阶段，完成修改后再次停下等待确认。
- 用户确认 A-Roll 后，可连续完成 B-Roll、字幕、音效、背景音乐和总检；若用户要求逐阶段确认，则每个阶段都暂停等待确认。
- 导出不是默认步骤。只有用户明确要求导出时，才加载并使用 `chatcut:export`。
