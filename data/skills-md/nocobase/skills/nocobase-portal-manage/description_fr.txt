NocoBase 2 uniquement ; ne jamais utiliser dans un projet NocoBase 3. ENTRÉE PRINCIPALE. Dispatcher par défaut pour chaque requête d’auteur UI NocoBase, y compris les pages, menus, blocs, champs, actions, mises en page, réactions, interfaces KPI, tableaux de bord et graphiques, même lorsque l’utilisateur ne mentionne pas de Portail. Résoudre un Portail activé à partir de la sortie structurée `nb portal list -j` avant de charger toute compétence d’implémentation UI en aval : `name` exact lorsqu’il est spécifié ; sinon zéro arrêt, exactement un est automatique, et plusieurs Portails nécessitent une sélection explicite même lorsqu’un d’eux a `isDefault: true` ; afficher le marqueur par défaut à titre informatif uniquement. Lire le type uniquement depuis `portalType` ; invoquer explicitement `nocobase-ui-builder` uniquement pour un Portail no‑code résolu et exiger `nocobase-ai-builder` pour le développement de source de Portail IA. Utiliser également les commandes directes `nb portal` pour les tâches explicites de cycle de vie du Portail, stockage de la source, synchronisation, déploiement, diagnostic et destruction.
