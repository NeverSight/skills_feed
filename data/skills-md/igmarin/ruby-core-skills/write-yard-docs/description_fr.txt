À utiliser lors de l'écriture de la documentation YARD pour les API publiques Ruby : chaque méthode publique DOIT avoir les balises `@param`, `@return [Hash]` et `@raise`, documenter `self.call` séparément de `#call`, lister chaque exception avec sa propre balise `@raise`, utiliser `@example` pour les constructions au niveau du module, `@see` pour les références croisées, suivre les conventions d'annotation de type YARD `@return`, ajouter des balises explicites Les sous-tâches YARD après l'implémentation dans les listes de tâches, conservez tout le texte YARD en anglais sauf demande contraire, exécutez `yard stats --list-undoc` pour vérifier la couverture et chargez les fichiers de ressources étendus uniquement lorsque leur contenu spécifique est nécessaire. Mots déclencheurs : YARD, documents en ligne, documentation de méthode, documents API, interface publique, rdoc, balise return, balise raise.
