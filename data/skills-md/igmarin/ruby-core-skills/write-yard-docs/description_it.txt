Da usare quando si scrive la documentazione YARD per le API pubbliche Ruby: ogni metodo pubblico DEVE avere i tag `@param`, `@return [Hash]` e `@raise`, documentare `self.call` separatamente da `#call`, elencare ogni eccezione con il proprio tag `@raise`, usare `@example` per costrutti a livello di modulo, `@see` per riferimenti incrociati, seguire le convenzioni di annotazione del tipo YARD `@return`, aggiungere sotto-attività YARD esplicite dopo l'implementazione negli elenchi di attività, mantieni tutto il testo YARD in inglese se non diversamente richiesto, esegui `yard stats --list-undoc` per verificare la copertura e carica i file di risorse estese solo quando è necessario il loro contenuto specifico. Parole chiave: YARD, documenti in linea, documentazione del metodo, documenti API, interfaccia pubblica, rdoc, tag return, tag raise.
