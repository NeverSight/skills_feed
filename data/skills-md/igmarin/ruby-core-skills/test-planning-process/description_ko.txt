테스트 경계를 선택하고, 테스트 사례(행복한 경로, 엣지 사례, 오류)를 식별하고, 테스트 코드를 작성하기 전에 첫 번째 실패한 테스트를 선택하고, 비즈니스 목표(HTTP/JSON 형태에 대한 요청, 도메인 불변성을 위한 서비스, 계산 단위)를 직접적으로 표현하는 가장 높은 경계에서 테스트하고, 합성 테스트 데이터(실제 프로덕션 값이 아님)를 요구하고, 'tdd-process'로 진행하기 전에 실패한 테스트 뼈대를 실행하여 Red를 확인합니다. 사용자가 테스트 적용 범위를 계획하거나, 테스트 경계를 결정하거나, 구현 전에 작성할 테스트를 결정해야 할 때 사용합니다. 트리거 단어: 테스트 계획, 테스트 계획, 테스트 경계, 테스트 매트릭스, 테스트 전략, 첫 번째 실패 테스트.
