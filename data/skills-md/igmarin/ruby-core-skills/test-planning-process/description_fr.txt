Sélectionne les limites des tests, identifie les cas de test (chemin heureux, cas limite, erreur), sélectionne le premier test échoué avant d'écrire un code de test, teste à la limite la plus élevée exprimant directement l'objectif commercial (demande de forme HTTP/JSON, service pour les invariants de domaine, unité de calcul), nécessite des données de test synthétiques (jamais de valeurs de production réelles) et exécute le squelette de test défaillant pour vérifier Red avant de passer au « processus tdd ». À utiliser lorsque l'utilisateur doit planifier la couverture des tests, déterminer les limites des tests ou décider quels tests écrire avant la mise en œuvre. Mots déclencheurs : plan de test, planification des tests, limites du test, matrice de test, stratégie de test, premier test échoué.
