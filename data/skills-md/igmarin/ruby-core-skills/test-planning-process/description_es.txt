Selecciona los límites de prueba, identifica casos de prueba (ruta feliz, caso límite, error), elige la primera prueba fallida antes de escribir cualquier código de prueba, prueba en el límite más alto que expresa directamente el objetivo comercial (solicitud de forma HTTP/JSON, servicio para invariantes de dominio, unidad para cálculos), requiere datos de prueba sintéticos (nunca valores de producción reales) y ejecuta el esqueleto de prueba fallido para verificar Red antes de continuar con el "proceso tdd". Úselo cuando el usuario necesite planificar la cobertura de las pruebas, determinar los límites de las pruebas o decidir qué pruebas escribir antes de la implementación. Palabras desencadenantes: plan de prueba, planificación de pruebas, límites de prueba, matriz de prueba, estrategia de prueba, primera prueba fallida.
