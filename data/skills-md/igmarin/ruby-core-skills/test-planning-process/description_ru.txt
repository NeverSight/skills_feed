Выбирает границы теста, идентифицирует тестовые случаи (счастливый путь, крайний случай, ошибка), выбирает первый неудачный тест перед написанием любого тестового кода, тестирует на самой высокой границе, непосредственно выражающей бизнес-цель (запрос формы HTTP/JSON, сервис для инвариантов предметной области, модуль для вычислений), требует синтетических тестовых данных (никогда не реальных производственных значений) и запускает скелет неудачного теста для проверки Red перед переходом к `tdd-process`. Используйте, когда пользователю необходимо спланировать тестовое покрытие, определить границы тестирования или решить, какие тесты написать перед реализацией. Триггерные слова: план тестирования, планирование тестов, границы тестирования, матрица тестирования, стратегия тестирования, первый неудачный тест.
