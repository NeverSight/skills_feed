Erzwingt Rot-Grün-Refactor mit harten Gates: Die rote Phase schreibt einen fehlgeschlagenen Test, der bei der Assertion (nicht Syntax/Konfiguration) fehlschlagen MUSS, und präsentiert Test+Fehler, bevor fortgefahren wird, führt nach jeder Phase Tests für die spezifische Datei (nicht die vollständige Suite) aus, die grüne Phase schreibt nur minimalen Code zum Bestehen und stoppt dort, die Refactor-Phase führt den Test nach jeder Mikroänderung aus und MUSS durchgehend grün bleiben. Generiert fehlgeschlagene Testfälle, validiert Testfehler vor dem Fortfahren und grenzt die Implementierung hinter das Bestehen von Red-Phase-Prüfungen ein. Wird verwendet, wenn der Benutzer einen TDD-Workflow anfordert, darum bittet, zuerst Tests zu schreiben, die Rot-Grün-Refaktor-Methodik erwähnt oder Triggerwörter verwendet: TDD, Test-zuerst, Test-Gate.
