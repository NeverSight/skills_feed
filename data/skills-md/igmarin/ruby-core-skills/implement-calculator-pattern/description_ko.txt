`Factory.for(entity)`를 통해 SERVICE_MAP 라우팅을 사용하여 변형 기반 계산기를 구축할 때 사용합니다(허용된 진입점만 — 직접 인스턴스화 금지). BaseService는 `should_calculate?`인 경우 `calculate`→`compute_result`를 정의하고, NullService에는 `should_calculate?`=false+`compute_result`=nil이 있으며, 구체적인 서비스는 두 메서드를 모두 재정의하고 다음에서 `super`를 호출해야 합니다. `should_calculate?` — 각 구성 요소는 순서대로 테스트됩니다(스펙 작성 → 실행 → Red 확인 → 구현 → 실행 → 다음 구성 요소 전에 Green 확인, NullService 및 구체적인 내용을 한 단계로 축소하지 않음). 테스트 범위에는 명명된 변형, 비활성 계획, 없음 계획 및 알 수 없는 변형 컨텍스트가 포함됩니다. 변형별 스캐폴드 테스트. 트리거 단어: 전략 패턴, 팩토리 패턴, null 개체 패턴, 변형 계산기, 디스패치 테이블, SERVICE_MAP, 무작동 폴백.
